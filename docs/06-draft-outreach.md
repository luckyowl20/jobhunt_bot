# 06 — Optional outreach drafts

Load the accepted job row, verified contact record, tailored document paths, application-status record, and approved voice. Create one plain-text file per accepted job if outreach is enabled. Never send it as part of this pipeline.

Use `To`, optional `Attention`, `Subject`, a brief body, signature, and an attachment checklist. Write two or three short paragraphs: identify the role, give one or two supported fit points, then make a modest request for review or routing. Be warm, professional, and direct. Avoid generic AI phrasing, exaggerated enthusiasm, invasive personalization, or false familiarity.

Say “I recently applied” only when the user confirms submission for that job. Otherwise use truthful interest/preparation wording. A history entry means considered, not applied. Mention a recommendation only if it exists and is intended for this message; do not imply it is attached when it is merely available on request.

Use only a supported email. For a company inbox, identify its routing function and put a relevant person in `Attention` only with evidence. If no verified address exists, keep `To` blank, record a public contact route, and mark the draft `recipient unresolved`.

Save under `recruiter_email_drafts/company_position_YYYY-MM-DD.txt`, using the manifest job-key mapping. Use `templates/outreach.template.txt`. Check names, company, role, job ID, status, factual statements, and exact intended attachment filenames. Keep the drafts out of Git with other private outputs.
